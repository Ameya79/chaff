## Context & Problem
Images without `alt` attributes or with low-quality placeholder text (such as `alt="image"`, `alt="graphic"`, or `alt="photo"`) are common failure modes in AI-generated templates. When an `alt` attribute is omitted, screen readers attempt to announce the image by reading out the raw source URL or internal asset hash, creating noisy and bewildering audio feedback. Conversely, decorative images (such as background blur shapes, dividers, and abstract geometric accents) that lack `alt=""` and `aria-hidden="true"` clutter the screen reader's virtual buffer with pointless interruptions.

## Detection Logic
Static AST analysis scans all `<img>` tags and Next.js `<Image>` components to verify:
1. The `alt` attribute is explicitly present.
2. The `alt` text does not match generic placeholder words: `^(?:image|photo|icon|graphic|picture|placeholder|banner|illustration)$` (case-insensitive).
3. If an image is identified as decorative via filename or styling, it must declare `alt=""` and `aria-hidden="true"`.

## Remediation Steps
1. For informative images (diagrams, charts, product photos), write concise, accurate descriptions conveying the key information or takeaway: e.g., `alt="Quarterly revenue chart displaying 28% growth across enterprise plans"`.
2. For purely decorative graphics, set empty alt text and hide from assistive technology: `alt="" aria-hidden="true"`.
3. Never start alt text with redundant phrases like "Image of" or "Picture of", as screen readers already announce the presence of an image element.
4. For complex infographics, provide a brief summary in `alt` and link to an accessible data table or text transcription below the graphic.

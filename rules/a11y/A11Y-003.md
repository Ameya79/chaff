## Context & Problem
Icon-only buttons—such as hamburger menus, search triggers, shopping cart toggles, close buttons (`X`), and social media icons—are ubiquitous in modern web interfaces. AI code generators frequently render an SVG icon directly inside a `<button>` without providing an accessible name. In the accessibility tree, this button has no name property. Screen readers announce it simply as "button" or attempt to read internal SVG path descriptions, rendering the interface unusable for blind or low-vision users.

## Detection Logic
Static AST analysis traverses all interactive elements (`<button>`, `<a>`, `[role='button']`, `[role='link']`) and checks for accessible name computation:
1. Presence of child text nodes.
2. Presence of a non-empty `aria-label` attribute.
3. Presence of an `aria-labelledby` referencing an existing DOM element.
4. Presence of an embedded `.sr-only` visually-hidden text span.
Flags any interactive node lacking all four naming mechanisms.

## Remediation Steps
1. Add a clear, action-oriented `aria-label` to every icon-only button: `aria-label="Close dialog"` or `aria-label="Search documentation"`.
2. Alternatively, embed a visually-hidden span inside the button: `<span className="sr-only">Close dialog</span>`.
3. Mark decorative embedded SVG icons with `aria-hidden="true"` and `focusable="false"` to prevent screen readers from announcing redundant graphical elements.
4. Ensure the accessible name accurately describes the action performed rather than the visual icon appearance (e.g. use "Edit profile", not "Pencil icon").

## Verification
Run automated axe-core audit inspecting the `button-name` and `link-name` rules. Open browser DevTools Accessibility panel and verify that every interactive icon element displays a valid, descriptive computed accessible name.

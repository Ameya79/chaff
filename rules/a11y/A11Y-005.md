## Context & Problem
Assistive technology users utilize heading navigation (pressing the 'H' key in screen readers) to browse page outlines and locate specific sections quickly. AI code generators often pick heading elements based purely on visual styling (e.g. picking `<h4>` because it happens to look smaller, or repeating `<h1>` for every card banner). This breaks the sequential document outline, creating skipped levels (e.g., jumping from `<h1>` directly to `<h4>`) or scattering multiple `<h1>` elements across a single view. The resulting confusion deprives users of structural comprehension.

## Detection Logic
Static AST analysis extracts all heading elements (`<h1>` through `<h6>`) in DOM order per route. Flags:
1. Pages containing zero or more than one `<h1>` element.
2. Any heading tag whose numerical level increases by more than 1 compared to the immediately preceding heading (e.g., `<h2>` followed by `<h4>`, skipping `<h3>`).

## Remediation Steps
1. Structure each page with exactly one primary `<h1>` element representing the main topic or purpose of the page.
2. Nest section headings sequentially: major sections use `<h2>`, subsections use `<h3>`, and nested items use `<h4>`.
3. Separate visual styling from semantic structure: use Tailwind typography utilities (such as `text-lg font-semibold`) to style headings rather than misusing heading tags to achieve smaller text sizes.
4. Ensure headings contain substantive descriptive text rather than empty nodes or purely decorative images.

## Verification
Run axe-core audit inspecting `heading-order` and `page-has-heading-one`. In the browser accessibility tree, verify that the heading hierarchy forms a clean, unbroken sequential tree starting from a single `h1`.

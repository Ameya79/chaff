## Context & Problem
System status badges, form validation errors, active connection indicators, and dashboard health dots frequently rely solely on color shifts (e.g. green for operational, red for error, yellow for warning) without secondary visual cues. Approximately 8% of men and 0.5% of women experience red-green color vision deficiency (deuteranopia or protanopia). For these users, red and green status dots appear virtually identical in hue and luminance. Relying purely on color violates WCAG 2.1 Success Criterion 1.4.1 (Use of Color), causing users to misinterpret critical system alerts.

## Detection Logic
Heuristic and AST analysis inspects conditional class bindings involving status color palettes (`text-red`, `bg-red`, `text-green`, `bg-green`, `border-emerald`, `text-amber`) applied to status elements, indicators, or error messages. Flags cases where the rendered output lacks accompanying distinct icon glyphs, text labels (`Active`, `Offline`, `Error`), or typographical markers (underlines, bolding, badges).

## Remediation Steps
1. Pair every status color with a distinct icon glyph: use a checkmark for success, an exclamation triangle for warning, an octagonal stop icon for errors, and an info circle for neutral notices.
2. Include explicit textual state descriptions alongside or inside badges: render `<span>Active</span>` or `<span>Degraded</span>` instead of bare colored circles.
3. For form validation errors, render an error message string with an icon below the input, rather than merely coloring the input border red.
4. For inline links within body text, maintain an underline or distinct typographical treatment so links are distinguishable from non-linked text regardless of color vision.

## Verification
Simulate deuteranopia, protanopia, and achromatopsia (monochrome grayscale) in browser DevTools Rendering tab. Verify that all system states, form validation flags, and dashboard statuses remain immediately distinguishable without reliance on color hues.

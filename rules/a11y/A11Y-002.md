## Context & Problem
Designers and AI code generators frequently apply `outline: none` or Tailwind's `focus:outline-none` to interactive elements to eliminate the default browser focus ring, which is perceived as aesthetically unappealing. Removing this indicator without creating an authored alternative completely destroys accessibility for keyboard navigators, screen reader users, and motor-impaired individuals using switch devices. Without a visible indicator, users cannot tell which button, link, or input currently holds focus, turning sequential navigation into guesswork.

## Detection Logic
Static source scanner inspects CSS files, Tailwind class strings, and styled components for instances of `outline: none`, `outline: 0`, `focus:outline-none`, or `focus:ring-0` that are not accompanied by an explicit `:focus-visible` or `focus-visible:outline` style declaration. The scanner flags any interactive component where focus indicator styling has been suppressed without replacement.

## Remediation Steps
1. Author distinct keyboard focus styles using `:focus-visible` rather than generic `:focus`, ensuring mouse users do not see outlines on click while keyboard users receive unmistakable visual indicators.
2. Configure focus indicators with at least 2px width and 2px offset: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-stone-900`.
3. Ensure focus ring color provides at least 3:1 contrast against both the component surface and the surrounding canvas background.
4. On dark backgrounds, use high-contrast white or light accent rings: `dark:focus-visible:outline-white dark:focus-visible:outline-offset-2`.

## Verification
Navigate through the application exclusively using the `Tab` and `Shift+Tab` keys. Verify that every interactive control (links, buttons, form inputs, disclosure accordions) displays a crisp, high-contrast focus ring with zero visual ambiguity.

## Context & Problem
React and Next.js applications assembled by AI agents routinely construct entire page architectures using nested `<div>` elements styled with classes like `.header`, `.main-container`, and `.footer-wrapper`. Because `<div>` elements have no semantic role in the accessibility tree, screen readers cannot construct page landmark shortcuts. Non-sighted users rely on landmark navigation keys (e.g. pressing 'D' or 'M' in NVDA/JAWS) to jump directly to primary content, skip navigation bars, or access sidebars. Without semantic landmarks, users must endure tedious linear tabbing through dozens of repetitive header links.

## Detection Logic
Static AST analysis checks top-level page and layout components (`layout.tsx`, `page.tsx`, `App.tsx`) to verify the presence of core HTML5 landmark elements (`<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`) or explicit ARIA roles (`role="banner"`, `role="navigation"`, `role="main"`, `role="contentinfo"`, `role="complementary"`). Flags any layout where the primary page content is wrapped exclusively in generic `<div>` containers.

## Remediation Steps
1. Replace top-level container divs with semantic HTML5 elements: `<header>` for page banners, `<nav>` for navigation groupings, `<main>` for primary unique page content, `<footer>` for copyright and secondary links, and `<aside>` for supplementary sidebars.
2. Ensure every page contains exactly one `<main>` landmark with `id="main-content"`.
3. Provide a skip-to-content link at the very top of the DOM: `<a href="#main-content" className="sr-only focus:not-sr-only focus:fixed focus:top-4 focus:left-4 z-50">Skip to content</a>`.
4. If multiple `<nav>` elements exist on a page, differentiate them using `aria-label`: `<nav aria-label="Main">` and `<nav aria-label="Footer">`.

## Verification
Execute axe-core audit inspecting `landmark-one-main` and `region`. In browser DevTools Accessibility tree, confirm that `banner`, `navigation`, `main`, and `contentinfo` landmark roles are clearly populated and navigable.

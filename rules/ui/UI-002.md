## Context & Problem
AI tools routinely apply `bg-clip-text text-transparent bg-gradient-to-r` to major headings. This causes rendering artifacts, clips character descenders, fails WCAG contrast compliance across varying background luminosities, and feels like a cheap visual gimmick. Furthermore, text selection on clipped gradient headers renders awkwardly across Safari, Chrome, and Firefox.

## Detection Logic
Static AST and regex search detects the concurrent appearance of `bg-clip-text` and `text-transparent` (or CSS properties `-webkit-background-clip: text` and `-webkit-text-fill-color: transparent`) on heading tags (`h1` through `h4`) or elements carrying heading ARIA roles. The scanner flags gradients spanning multiple distinct color families (such as purple-to-pink or cyan-to-orange).

## Remediation Steps
1. Remove `bg-clip-text`, `text-transparent`, and `bg-gradient-to-*` utility classes from heading declarations.
2. Apply high-contrast solid semantic text color tokens (for example `text-stone-900 dark:text-stone-50`).
3. Enhance typographic sophistication via tight letter spacing (`tracking-tight`), crisp font weights (`font-semibold`), and proportional line height.
4. Ensure text contrast against underlying surfaces exceeds WCAG AA requirements (4.5:1 minimum).

## Verification
AST scan confirms zero instances of `bg-clip-text` on headings. Measure computed text contrast ratio across light and dark themes to confirm compliance with WCAG AA standards.
